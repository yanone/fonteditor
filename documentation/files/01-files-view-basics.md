# Files View Basics

The Files view is the operational center for how your source files enter and leave Counterpunch. It is also where storage context is defined, which directly affects how safely and predictably your project updates are written. Spending time here early prevents many common beginner mistakes around missing files and uncertain save targets.

## Summary

The Files view is where you open fonts, control where your work is stored, and switch between in-browser memory and local disk folders. A clear mental model of these storage contexts is essential for reliable daily work, especially when moving between quick experiments and production sources.

## Core Concepts

Counterpunch distinguishes between two storage contexts. **Memory** provides in-browser storage ideal for quick experiments and temporary work, while **Disk** offers direct access to a local folder when you grant the appropriate permissions. Understanding this distinction helps you choose the right storage approach for different types of work.

## Typical Tasks

Most file operations follow a familiar pattern. You can open a font from any accessible folder, check whether your current file resides in Memory or Disk storage, and save changes back to the same location when you're ready to preserve your work.
